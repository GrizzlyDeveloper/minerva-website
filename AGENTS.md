# Minerva website recurring updates

Before a launcher publication read the companion launcher repository's
`docs/RELEASE_WORKFLOW.md` and its `AGENTS.md`. Every authorized release must keep
RU/EN release history, download metadata and affected help guides current.

Help content is authored in help-content.mjs (and imported versioned editorial
modules), generated by build-help.mjs and indexed/rendered by help.js. Update both
languages, supported versions/defaults, troubleshooting, related links and the
sitemap. Label source review separately from runtime/in-game acceptance.

Do not publish unrelated local changes accidentally. Build a reviewed patch from
the live site or copy the live static tree first, preserve unrelated assets and
routes, back up before switching, and verify the public result at desktop/mobile
widths. Never publish account/session data or service credentials in static files.

Keep source/docs in Git AND push the source backup branch. Any new mandatory
recurring workflow needs an instruction/runbook linked from AGENTS.md; do not
rely on chat history surviving compaction. User publication authorization persists
for its stated scope; do not request duplicate confirmation without a real reason.
